# Deploying Vivace

This guide deploys Vivace as **one web portal** on Render (Express serving the Angular build), with **MongoDB Atlas** for storage and an optional second Render service for the Python ML engine. Everything below fits in the free tiers.

```
            ┌────────────────────────────── Render ──────────────────────────────┐
 users ──▶  │  vivace (Node)  ── ML_SERVICE_URL ──▶  vivace-ml (Python, optional) │
            └───────┬───────────────────────────────────────────┬────────────────┘
                    │ MONGODB_URI                                │ GEMINI_API_KEY (optional)
              MongoDB Atlas (M0)                          Google Gemini API
```

---

## 1. MongoDB Atlas

1. Sign in at https://cloud.mongodb.com and create a project (e.g. *Vivace*).
2. **Create a cluster** → choose **M0 (Free)**, a region close to your Render region (e.g. *Mumbai* or *Singapore*), name it `vivace`.
3. **Database Access** → *Add New Database User* → username `vivace_app`, password auto-generated (save it), role *Read and write to any database*.
4. **Network Access** → *Add IP Address* → `0.0.0.0/0` (Render's outbound IPs change on the free plan). The database user's password is the actual protection, so keep it long and random.
5. **Connect** → *Drivers* → copy the connection string and add the database name `vivace`:

   ```
   mongodb+srv://vivace_app:<password>@vivace.xxxxx.mongodb.net/vivace?retryWrites=true&w=majority
   ```

   URL-encode special characters in the password (`@` → `%40`, `#` → `%23`, …).

Collections (`users`, `interviews`, `mistakes`, `coachmessages`, `abtests`) and the GridFS bucket (`media.files`, `media.chunks`) are created automatically on first use. Indexes are created by Mongoose at start-up.

## 2. Gemini API key (optional)

1. Go to https://aistudio.google.com/apikey → *Create API key*.
2. Keep it for step 3. Without it Vivace runs entirely on its offline engines — every feature still works.

## 3. Render — Blueprint (recommended)

1. Push the project to a GitHub repository (the zip contains everything; `git init && git add . && git commit -m "Vivace" && git push`).
2. In Render: **New → Blueprint** → connect the repository. Render reads `render.yaml` and proposes two services:
   * **vivace** — Node web service. Build: `npm run render-build`. Start: `npm start`. Health check: `/api/health`.
   * **vivace-ml** — Python web service in `ml-service/`. Build: `pip install -r requirements.txt`. Start: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
3. Fill in the prompted environment variables for **vivace**:
   * `MONGODB_URI` — the Atlas string from step 1.
   * `GEMINI_API_KEY` — from step 2, or leave blank.
   * `JWT_SECRET` is generated by Render; `ML_SERVICE_URL` is linked to the ML service's URL automatically; `NODE_ENV=production` is set.
4. **Apply**. The first build takes a few minutes (it installs both packages and compiles Angular).
5. Open `https://vivace-<suffix>.onrender.com/api/health`. You should see:

   ```json
   { "status": "ok", "db": "up", "ai": "gemini", "ml": "up" }
   ```

   `ai` is `offline` without a Gemini key; `ml` is `disabled`/`down` if you skipped the ML service.
6. Open the root URL, create an account, and run a short text interview to confirm everything end to end.

> **Don't want the ML service?** Delete the `vivace-ml` block and the `ML_SERVICE_URL` entry from `render.yaml` before applying (or remove the service later and clear the variable). The portal falls back to its JavaScript engines.

## 4. Render — manual setup (without Blueprint)

**Portal**: New → *Web Service* → your repo.

| Setting | Value |
|---|---|
| Runtime | Node |
| Build command | `npm run render-build` |
| Start command | `npm start` |
| Health check path | `/api/health` |
| Environment | `NODE_VERSION=22.12.0`, `NODE_ENV=production`, `MONGODB_URI=…`, `JWT_SECRET=<48+ random chars>`, optional `GEMINI_API_KEY`, optional `ML_SERVICE_URL` |

Generate a secret with `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`.

**ML service** (optional): New → *Web Service* → same repo, **Root directory** `ml-service`, runtime Python, build `pip install -r requirements.txt`, start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, env `PYTHON_VERSION=3.11.9`. Copy its URL into the portal's `ML_SERVICE_URL`.

## 5. Docker (any host: Railway, Fly.io, a VPS, Azure, …)

```bash
docker build -t vivace .
docker run -p 8080:8080 \
  -e MONGODB_URI="mongodb+srv://…" \
  -e JWT_SECRET="$(openssl rand -hex 48)" \
  -e GEMINI_API_KEY="…" \
  vivace

# ML service
docker build -t vivace-ml ./ml-service
docker run -p 8001:8001 vivace-ml
```

Everything on one machine (MongoDB included): `docker compose up --build`.

## 6. After deploying

* **HTTPS** is automatic on Render; cookies are marked `Secure` in production, so always use the `https://` URL.
* **Camera & microphone** require HTTPS (or `localhost`). They won't work on a plain `http://` IP address.
* **Custom domain**: Render → service → *Settings → Custom Domains*. No code change needed — the API and app share the origin.
* **Cold starts**: free Render services sleep after 15 idle minutes. Upgrade to a paid instance or ping `/api/health` periodically if you're demoing.
* **Storage**: recordings are stored in GridFS. A 10-minute low-bitrate video is ~25–40 MB; the free Atlas M0 has 512 MB, so delete old recordings (Report → *Delete this interview*) or move to M2+ for heavier use. `MAX_UPLOAD_MB` caps a single upload (default 40).
* **Logs**: Render → service → *Logs*. Gemini or ML failures are logged as warnings and the app keeps going on fallbacks.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| Deploy fails with `MONGODB_URI is required in production` | Set `MONGODB_URI` on the **vivace** service. |
| `JWT_SECRET must be set to at least 32 characters` | Set a longer secret (or let the Blueprint generate one). |
| `/api/health` shows `"db": "down"` / `MongoServerSelectionError` | Atlas *Network Access* must allow `0.0.0.0/0`; check the user/password and URL-encoding. |
| Build fails at `ng build` with "command not found" | Use `npm run render-build` (it installs the client's dev dependencies, which include the Angular CLI). |
| `"ai": "offline"` although a key is set | The key is invalid or quota is exhausted; check the logs for `[gemini]` warnings. The breaker retries after 60 s. |
| `"ml": "down"` | The ML service is asleep or failed to build; open its URL `/health`. The portal still works. |
| Camera/mic prompt never appears | Use HTTPS, allow permissions in the address bar, and close other apps using the camera. |
| Voice answers don't transcribe in Firefox/Safari | Those browsers lack Web Speech recognition. Add a Gemini key for server transcription, or use *Type instead*. |
| Logged out immediately after login | You're on `http://` in production (Secure cookie dropped). Use the HTTPS URL. |

## 8. Pre-flight checklist

- [ ] Atlas cluster, user and network access configured
- [ ] `MONGODB_URI`, `JWT_SECRET`, `NODE_ENV=production` set on the portal
- [ ] (optional) `GEMINI_API_KEY` set
- [ ] (optional) ML service deployed and `ML_SERVICE_URL` set
- [ ] `/api/health` returns `"status": "ok"`
- [ ] Register → text interview → report works
- [ ] Voice/video tested over HTTPS in Chrome
